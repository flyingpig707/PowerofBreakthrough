## 需要处理的问题

### P1 表格不是 VitePress 可直接使用的 Markdown 表格

当前 72 张表格采用 Pandoc 的简单表格或网格表格语法。Pandoc 能正确识别它们，但 VitePress 使用的 Markdown 解析器不能完整识别这种格式。

如果直接建站，可能出现列错位、边框字符进入正文、表格退化为普通文本等问题。附录中的问卷、评分表、SOP、RACI 和 KPI 表受影响最明显。

处理建议：在搭站前统一转换为标准管道表格；包含合并单元格或复杂布局的表格改为受控 HTML 表格或专用组件。

### P1 图片后残留 Pandoc 尺寸属性

27 处图片引用均带有类似以下内容：

```text
{width="4.330555555555556in" height="1.5125in"}
```

部分尺寸属性还被拆成两行。VitePress 不会把这些属性稳定地解释为图片尺寸，可能直接显示为正文文字。

处理建议：删除英寸尺寸属性，保留标准 Markdown 图片引用；图片宽度统一交给阅读站主题的 CSS 控制。

### P2 Word 与 Markdown 的作者署名不一致

Markdown 封面、前言署名和书末落款中包含“任国刚 吴鹏”。Word 主稿对应位置没有检出“吴鹏”。

这不是转换丢失导致的普通格式差异，需要作者确认最终署名。当前暂以已经导入的 Markdown 为基线，不自动删除或补写姓名。

### P2 整书 Markdown 的目录不应成为第二内容源

整书 Markdown 比分章稿多出的主要内容是带页码的 Word 目录。正文部分与当前 `book/` 一致。

网站目录应由 VitePress 根据 `book/` 和站点配置生成，不应继续维护这份静态页码目录，否则章节调整后会形成两个不同步的目录系统。

### P2 Word 字体不适合充当跨平台发布基线

Word 主稿大量使用 `Yuanti SC`、华文仿宋、华文宋体和华文楷体。使用标准文档渲染环境检查时，部分中文字体无法正确替代，165 页中的中文出现缺字现象。

这不影响 Markdown 正文完整性，但说明网站设计不能照搬 Word 字体配置。阅读站应使用明确的中文 Web 字体回退栈。

### P3 标题和横线需要网页语义化

章副标题目前仍以连续连字符开头，例如：

```text
## ------让城市被AI看见
```

内容没有缺失，但这种写法来自 Word 排版习惯。建站时应把装饰性交给 CSS，正文标题只保留真实文字，避免搜索、目录和无障碍阅读把连字符当作标题内容。

## Word 版式检查说明

Word 主稿共渲染 165 页。图片和表格对象数量与 Markdown 一致，没有发现对象缺页。由于主稿使用的部分中文字体在标准渲染环境中不可用，渲染结果存在中文缺字，不能据此评价最终印刷排版质量。

该限制不影响本次“内容是否完整”的判断。后续若要继续维护 Word 出版稿，应单独进行字体替换和印刷版式校验；它与当前网页建设是两条不同工作线。
